# 现代软件应用研发工作法与六步交付闭环 (App Engineering Playbook)

> **版本**：v1.0.0 (2026-09-14)  
> **核心渊源**：基于 CineDrama OS 多模态漫剧系统真实交付、商业级头部漫剧平台（如 LiBTV / 行业成熟工业管线）逆向对照、以及 Zod 运行时审查规范全量实战复盘提炼。  
> **适用范围**：AI Agent 应用、多模态系统、全栈 Web/SaaS、数据流与复杂工作流工程。

---

## 核心认知陷阱与破局口诀

### 致命陷阱
> **“代码写完了，跑通了一个 Demo，就以为做好了；但一到真实环境，网络一抖、模型一抽、输入一个空字符，整个系统立刻崩溃。”**

### 交付铁律口诀
> **官方先探路，摸清为何做；契约锁边界，空格不能漏。**  
> **外部皆不可信，容灾续跑留后手；套件轮番验，视听混沌全测透。**  
> **门禁全绿才言完，界面极简显功候。**

---

## 六步交付闭环（6-Stage Execution Framework）

### 阶段一：逆向官方与探究动因 (Scout & Understand 'Why')
**原则：绝不凭空臆造架构，动手前先花时间看官方与业界标杆如何设计，并深究其“为什么”。**

1. **研究模态与模块切分逻辑**：
   - 官方为什么坚持“模态专精”而非“全包全揽”？因为没有单一模型在文本、分镜、视频、声音上全能且商用最优。每个供应商只承担自己最擅长且真正具备的能力。
2. **探究官方的保底与退路（Human-in-the-Loop）**：
   - 工业级漫剧平台为什么设计 `Bridge`（本地桥）与 `drop/` 文件夹？因为在线 AI 视频有肢体扭曲或额度耗尽的必然概率。给创作者留出外部 ComfyUI / Midjourney / Sora 投递渠道，是工业级成片率的生命线。
3. **核实真实协议与输入参数**：
   - 对齐官方商汤 U1 为什么走 `chat/completions + modalities: ["image"]` 并严格计算像素宽高，绝不自行发明非标准协议。

---

### 阶段二：契约先行与冻结边界 (Contract-First & Real Boundaries)
**原则：用真实运行时强类型 Schema（如 Zod / Serde / Typed Models）卡死输入输出，杜绝 `any` 穿透和虚假防线。**

1. **严防“语法通过等于逻辑安全”的欺骗**：
   - **典型细节教训**：`z.string().min(1)` 遇到 `"   "` 纯空格会误判通过（长度为 3）；必须严格写成：
     `	s
     z.string().trim().min(1, "字段不能为空")
     `
2. **契约落位在真实物理边界**：
   - 契约必须部署在 HTTP 控制器入口、WebSocket 消息解析点、LLM 输出反序列化点；
   - 校验失败必须抛出语义清晰的结构化 `400 Bad Request` 与具体字段定位，严禁在生产环境静默吞错导致下游白屏。

---

### 阶段三：预设最坏情况与混沌容灾 (Design for Chaos & Resilience)
**原则：在现代分布式与 AI 应用中，外部故障不是“意外”，而是“必然”。**

1. **网络超时与 503 频发**：
   - 实现 **指数退避重试（Exponential Backoff with Jitter）**，给每次重试加抖动，防止重试风暴击垮上游。
2. **长时间任务意外中断**：
   - 实现 **步骤级快照持久化（Step Snapshot）与断点续跑（Resume Job）**。7 步漫剧第 5 步挂掉，恢复时秒级跳过前 4 步，精准接续剩余工作。
3. **大模型输出格式抽搐**：
   - 实现 **LLM 自纠偏闭环（Self-Correction Loop）**。提取异常时，将 Schema 错误说明回喂给模型并动态降温重试，耗尽次数后平滑模板兜底。
4. **多模态流媒体健康与时序对齐**：
   - 二进制 WAV 44 字节头校验、RMS 静音与削顶爆音截断；
   - 音画时序动态拉伸（Pacing Calibration）：配音长于规划分镜时自动拉伸镜头时长，坚决不让台词被掐断。

---

### 阶段四：专精质量套件全量检验 (Domain-Specific Verification Suites)
**原则：普通的“功能单测”只会测开发者想好的正常分支。必须构建 5 大维度专项检验套件。**

| 套件类型 | 核心检验目标 | 实操手段与断言范式 |
| :--- | :--- | :--- |
| **1. 契约边界套件** | 拦截恶意与畸形输入 | 纯空格、超长文本、非法枚举、空对象，必须断言返回标准 400 校验结构。 |
| **2. 领域一致性套件** | 长链路业务状态不漂移 | 漫剧角色视觉特征锚点锁定、前序集阵亡角色禁止无闪回复活、未解伏笔跨集继承。 |
| **3. 视听健康套件** | 资源物理合规与时序同步 | PCM 格式魔数、音频能量阈值检验、音画时长动态伸缩漂移量 < 30ms。 |
| **4. 混沌自愈套件** | 外部断网故障自保 | 注入 503/Timeout 断言指数退避自愈成功；注入进程崩溃断言断点续跑 100% 恢复。 |
| **5. 效果裁决套件 (LLM Judge)** | 防止生成毫无意义的废话水文 | 四维量规加权裁决（戏剧张力 35%、人设 30%、分镜 25%、视听 10%），低于 70 分强制回炉。 |

---

### 阶段五：双门禁铁律与实测取证 (Evidence-Based Iron Gates)
**原则：No Evidence, No Claim。没有看到终端最新的执行输出，严禁宣称完成。**

发布前必须在终端顺序执行：
`powershell
# 门禁 1：严格类型检查（编译级保障）
npm run typecheck    # 必须 0 错误、0 警告、退出码 0

# 门禁 2：全量专项套件实测（运行时全量回归）
npm test             # 必须 100% 测试用例绿灯全亮
`
- 严禁为了“让测试通过”而去弱化断言或跳过用例。
- 必须基于报错日志顺藤摸瓜定位真实根因并修复。

---

### 阶段六：极简创作者体验封装 (Creator-Facing Polish)
**原则：底层系统可以精密如航空母舰，呈现给用户的操作必须极简如家用电器。**

1. **面向用户隐藏技术细节**：创作者只关心“故事输入 -> 漫剧生成 -> 播放导出”，不需要理解底层 DAG、拓扑排序和微内核。
2. **把底层自愈转化为给用户的安全感**：
   - 音画校准完成 -> 展示胶囊徽章：`🟢 16kHz PCM 广播级`；
   - 角色锚点生效 -> 展示胶囊徽章：`🟢 萧凡 (黑袍冷峻) 形象已锁定`；
   - 快照持久化 -> 展示胶囊徽章：`🔄 进度实时保存·支持断点恢复`。
3. **保留人工把控权（Human Agency）**：
   - 永远给用户提供“重新生成”、“微调台词”、“手动上传/替换素材”的选项。

## 终极交付检查清单（Checklist）

- [ ] 是否已比对官方实现，并弄清其架构与退路设计的“为什么”？
- [ ] 所有入参是否均通过 `trim().min(1)` 防空格穿透的严格 Schema 校验？
- [ ] 外部 API 调用是否有超时限制、指数退避重试与平滑兜底？
- [ ] 长周期任务是否有状态落库、步骤快照与断点续跑接口？
- [ ] 5 大专项质量套件（契约、一致性、多模态、混沌、质量裁决）是否全部实写？
- [ ] `typecheck` 退出码是否为 0，`test` 是否 100% 全绿灯并记录实测用时？
- [ ] 用户前端是否一目了然，有直观的健康胶囊徽章与手动调整通道？
