## 一、为什么普通创作者产品更需要这套检验套件？

面向普通网文作家、短剧编剧的 AI 创作软件，最致命的不是“功能少”，而是“暗坑多”：
1. **输入异常崩溃**：小白用户输入特殊符号、换行或超长文本，后台裸报 500，创作者不明就里；
2. **大模型幻觉与格式漂移**：大模型输出带有 Markdown 废话，导致 JSON 解析崩溃，生成流程卡死；
3. **低质水文无法把控**：生成内容无冲突、平铺直叙，创作者不知道哪里写得差；
4. **音频假声与音画腰斩**：TTS 生成空包静音或爆音，且配音比分镜长，播放时台词被硬生生切断；
5. **角色“融化”与变脸**：上一个镜头黑发青衫，下一个镜头金发西装，视觉严重不连贯；
6. **网络波动前功尽弃**：生成到第 6 步断网或报错，数十分钟的生成进度全丢，需要从头重新花钱跑；
7. **长剧吃书与死人复活**：多集制作时，前一集阵亡的角色在后一集无闪回直接复活登场。

**只有通过全套自动化的针对性检验套件，才能在上线前把深藏在底层的边界死角和隐蔽 Bug 全部逼出来并自动自愈。**

## 二、七大核心工程保障套件详解

### 1. Zod 运行时契约校验套件 (`test/zod-validation.test.ts`)
* **核心职责**：在系统所有边界（HTTP 请求、流程节点入参、大模型输出、数据库持久化）建立强类型防穿透护栏；
* **断言能力**：
  - 拦截无效画幅、负数时长、非法 URL，统一返回标准 HTTP 400 与清晰中文诊断；
  - 严禁 `any` 穿透，消除字段拼写错误与脏数据入库。

### 2. 大模型结构化输出自我纠错闭环套件 (`test/llm-repair-loop.test.ts`)
* **核心职责**：实现 `generateStructured<T>()` 自愈机制，杜绝大模型 JSON 格式崩溃；
* **自愈机制**：
  - 第 1 次调用若提取 JSON 失败或字段缺失，提取具体 Zod 错误信息注入修复提示词；
  - 动态降温至 0.1，启动最多 2 次针对性纠错重试；
  - 连续重试仍失败时，平滑降级至业务安全预设模板，保证流水线永不中断。

### 3. Prompt Evals & 影视级质量裁决套件 (`test/eval-judge-suite.test.ts`)
* **核心职责**：工业级量化评审短剧质量，实现 S/A/B/C 级分级与针对性改稿锦囊；
* **评审量规 (Rubrics)**：
  - 戏剧张力与矛盾冲突 (35%)：黄金开局、反转力度；
  - 台词对白与人设鲜明 (30%)：情绪张力，严禁说明书式废话；
  - 分镜画面与运镜节奏 (25%)：景别过渡、电影感视听；
  - 视听流转与节奏控制 (10%)：台词与画面时长契合度；
* **拦截能力**：敏锐检测平淡水文，自动压至 C 级并拦截，给出专业编剧修改建议。

### 4. 多模态视听流异常断言与健康套件 (`test/media-integrity-suite.test.ts`)
* **核心职责**：字节级 WAV PCM 容器解析与声学体检，实现音画时序自动对齐；
* **健康指标**：
  - 校验 44 字节标准 WAV 头部（`RIFF`/`WAVE`/`fmt `）；
  - 计算 RMS 能量分贝，拦截振幅全零的假声音与哑巴空包音；
  - 采样点振幅超限率拦截削顶爆音；
  - **音画时序校准 (AV Pacing Calibration)**：若 TTS 对白时长（如 3.96s）大于分镜规划（如 3.5s），自动向上以 0.1s 粒度拉伸分镜至 4.0s，从根源杜绝短剧播放时台词被切断。

### 5. 角色视觉与风格一致性断言套件 (`test/character-consistency-suite.test.ts`)
* **核心职责**：角色面部、发型、服饰与画风的跨镜头锁定与防漂移；
* **锁定机制**：
  - 从资产提取角色视觉特征锚点（Appearance & Wardrobe Tokens）；
  - 分镜生图前自动注入 `[角色锁定: 姓名 | 外观与服饰] + 风格标识`；
  - 审计分镜提示词对特征锚点的保留度（Recall），对低于 60% 的提示词实施自动增强补偿。

### 6. 网络波动与断点续生成容灾套件 (`test/chaos-resilience-suite.test.ts`)
* **核心职责**：防网络瞬态崩溃与长任务全自动接续续跑；
* **容灾机制**：
  - **指数退避重试 (Exponential Backoff + Jitter)**：针对 502/503、超时、连接被重置等临时波动，自动在 300ms、600ms、1200ms 后重试自愈；
  - **步骤级断点续跑 (Step-level Resumption)**：任务中断或失败后，点击续跑可自动识别已完成的步骤输出，跳过耗时上游节点，直接从中断点向后接续生成；
  - **幂等持久化**：保证断点恢复时数据库记录不产生重复垃圾数据。

### 7. 长篇多集连贯性与剧情伏笔检查套件 (`test/multi-episode-continuity-suite.test.ts`)
* **核心职责**：跨集全局剧本记忆库，严防吃书与矛盾；
* **连贯性控制**：
  - 全局剧本状态总账（Character Lore & Props Ledger）；
  - 严禁前序剧集中已阵亡角色无闪回/回忆标记在后续剧集中直接复活；
  - 跨集关键道具流转追踪；
  - 未解剧情伏笔与悬念自动递延注入下一集的剧本大纲与提示词中。

## 三、强制验收门禁标准操作程序 (Mandatory Inspection Gate SOP)

```powershell

npm run typecheck

# 2. 第二道门禁：全系统测试套件全量回归 (100% 绿灯通过)
```

1. **类型检查通过**：`tsc --noEmit` 退出码必须为 0，控制台零错误、零报警；

3. **无回归损耗**：历史已通过的测试用例不得被随意弱化、注释或删除。

## 六、商业级影视与漫剧架构深层设计哲学与对齐原因 (Architecture Philosophy & Rationale)

在对标业界头部商用漫剧平台（如 LiBTV、商业多模态流水线）与现代化设计规范（Zod、Cordis）后，明确以下架构决策的核心动因：

### 1. 为什么供应商按“模态专精”解耦，绝不搞“全能大包大揽”？
- **业界原因**：在真实 AI 漫剧工业界，没有单一厂商能在文本、生图、生视频、声音合成上全部达到商用最优且全部免费。
  - **SenseNova (商汤)**：只接入文本（`deepseek-v4-flash`）与图片（`sensenova-u1-fast`）。在 `sensenova.ts` 中对视频和 TTS 显式抛错拒绝，是因为商汤官方 Token 网关未提供视频与 TTS 接口。假装支持只会让用户在成片阶段遭遇静默黑天鹅。
  - **专业视频厂商**：快手可灵（Kling）、生数科技（Vidu）、火山引擎（Volcengine）才是视频的专门供应商。
  - **专业配音厂商**：Minimax、OpenVoice 负责专业音色克隆与情感对白。
- **CineDrama OS 对齐**：明确各 Provider 的真实能力边界，流水线按模型能力类型动态调度，拒绝虚假 Mock 掩盖无能力接口。

### 2. 为什么 SenseNova U1 要走 `chat/completions + modalities: ["image"]`？
- **架构动因**：商汤 U1 属于多模态融合架构，支持图生图（参考图）与文本对话提示词输入，并按宽高像素尺寸（1024/2048）精准控制。
- **CineDrama OS 对齐**：完全对齐标准 `resolveDimensions` 算法与 payload 结构，有 Key 时真实发起商汤 U1 生成，无 Key 或断网时才启用带景别的电影画幅底图。

### 3. 为什么中转设计了 `Bridge` 本地桥与 `drop/` 文件夹？
- **架构动因**：漫剧创作本质是 **Human-in-the-Loop（人机协同）**。在线 AI 生成视频常有崩坏、抽搐或额度耗尽的情况。工业级 Bridge 允许创作者将 ComfyUI、Midjourney、Google Veo 或 Sora 手动生成的素材投入 `drop/images/` 和 `drop/videos/`，系统自动吸纳建档，这是专业团队的保底生命线。

### 4. 为什么 Zod 契约检验必须严格遵守 `trim().min(1)`？
- **实战经验**：`z.string().min(1).trim()` 在输入纯空格（如 `"   "`）时会误判为通过（长度为 3），随后返回空字符串；必须写成 `z.string().trim().min(1)` 才能将纯空格判定为非法输入。这一细节是工业级审查中提炼出的实战铁律。
